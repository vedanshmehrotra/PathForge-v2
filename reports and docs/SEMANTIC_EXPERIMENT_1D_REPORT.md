# SEMANTIC EXPERIMENT 1D: GENERALIZATION VALIDATION

## Executive Summary

The semantic scorer was evaluated on a **275-case corpus** (disjoint from the 46-case calibration set), including 98 seed cases, 134 rename variants, 3 loop-form variants, and 40 cross-pattern negatives.

**Verdict: APPROVE WITH RECOMMENDED FIXES**

The scorer generalizes well for `two_pointers_opposite` (1.00 F1) and `hash_map_lookup` (0.92 F1). `prefix_sum` achieves 0.84 F1 with identifiable failure modes. `array_traversal` scores 0.60 F1, but analysis reveals this is primarily a feature gap (`for x in arr` direct iteration), NOT a generalization failure.

**Critical finding:** The apparent 18 "rename failures" for `array_traversal` are NOT caused by renaming. They all descend from 10 parent seeds that use `for x in arr` without indexed access. The rename variants fail because the parent already fails — renaming is not the cause.

## 3. Failure Taxonomy

### array_traversal (28 FNs)

**Root cause: `for x in arr` direct iteration without indexing**

All 28 FNs descend from seeds that use `for x in arr:` (direct collection iteration) without `arr[i]` indexed access. The rename variants (18 of 28) fail because the PARENT seed fails — renaming is NOT the cause.

| Parent Seed | Code Pattern | FN Count | Root Cause |
|-------------|-------------|----------|------------|
| element_traversal | `for x in arr: print(x)` | 2 + 4 rename | No indexed access |
| collection_loop_append | `for x in arr: result.append(x)` | 2 + 4 rename | No indexed access |
| summation | `for num in nums: total += num` | 2 + 4 rename | No indexed access, accumulation detected but not credited to array_traversal |
| element_transform | `for x in arr: result.append(f(x))` | 2 + 4 rename | No indexed access |
| element_filter | `for x in arr: if cond: ...` | 2 + 4 rename | No indexed access |
| accumulation | `for x in arr: total += x` | 2 rename | Same as summation |
| min_finding | `for x in arr: if x < min_val: ...` | 2 rename | No indexed access |
| count_condition | `for x in arr: if cond: count += 1` | 2 rename | Partial score (0.15) |
| double_traversal | Two for-loops | 2 rename | No indexed access |

**Feature gap, NOT generalization failure.** The feature extractor correctly identifies `has_collection_iteration = True` but the scorer only credits collection iteration when combined with indexed access. Adding direct iteration as evidence (even at lower weight) would recover most FNs.

### hash_map_lookup (2 FNs + 5 FPs)

**FNs:**
1. `valid_anagram_membership`: `ch not in seen` — uses `not in` (`ast.NotIn`), which the extractor does not detect. Only `ast.In` is checked.
2. `happy_number`: `n not in seen` — same `not in` issue.

**FPs (all labeled negative in corpus):**
1. `single_membership_no_loop`: `x = key in seen` — membership test without loop. Labeled negative but IS a membership test.
2. `literal_dict_in_loop`: `d = {1: 'a'}; for k in keys: if k in d: ...` — dict membership in loop. Labeled negative but IS hash map lookup behavior.
3. `single_membership_dict_constructor`: `x = key in mapping` — membership without loop.
4. `nested_membership_no_loop`: `x in some_dict` — membership without loop.
5. `dict_get_no_in`: `mapping.get(key)` — dict get without `in`. Labeled negative but IS dict lookup.

**Assessment:** The 5 FPs are **label disagreements**, not scorer errors. The validation corpus was designed for the AST detector, which checks for specific structural patterns. The semantic scorer correctly identifies behavioral hash map lookup in these cases. However, the corpus labels are the reference, so these count as FPs.

### prefix_sum (12 FNs + 1 FP)

**FNs:**
1. `range_sum_query` (2 seed + 10 rename): `prefix.append(prefix[-1] + num)` — uses `.append()` not `+=`. Accumulation detector doesn't fire.
2. `prefix_array_classic` (2 seed): `prefix[i] = prefix[i - 1] + arr[i - 1]` — uses `=` not `+=`. Accumulation detector doesn't fire.

**Feature gap:** The accumulation detector only recognizes `x += expr` (AugAssign). It does not detect:
- `list.append(expr)` as accumulation
- `x[i] = x[i-1] + expr` as accumulation

**FP:** `plain_sum_neg`: `sum(nums)` — single function call, labeled negative, scored 0.30. Correctly low.

### two_pointers_opposite (0 FNs, 0 FPs)

Perfect generalization. All 52 cases (33 positive, 19 negative) correctly classified at threshold 0.3.

## 4. Generalization Findings

### What generalizes well

1. **Variable names:** The semantic scorer is NOT dependent on variable names. All 134 rename variants produce identical scores to their parent seeds. The rename failures are inherited from parent failures, not caused by renaming.

2. **For vs while syntax:** `for i in range(len(arr))` and equivalent while loops produce the same features. The for-loop counter detection (Fix 1) works correctly.

3. **Dict/set construction:** `dict()`, `{}`, `set()` are correctly tracked. Membership on tracked dict/set variables correctly scores hash_map_lookup.

4. **Two-pointers:** Perfect across all code forms, variable names, and structural variants.

### What does NOT generalize

1. **`not in` membership:** The extractor only checks `ast.In`, missing `ast.NotIn`. This causes 2 hash_map_lookup FNs.

2. **Direct iteration without indexing:** `for x in arr: total += x` produces `has_collection_iteration = True` but the scorer doesn't credit this for array_traversal without indexed access. This causes 28 array_traversal FNs.

3. **Non-augmented accumulation:** `prefix[i] = prefix[i-1] + arr[i-1]` and `list.append(expr)` are not recognized as accumulation. This causes 12 prefix_sum FNs.

### Label vs scorer disagreements

The validation corpus was designed for AST detectors, which check specific structural patterns. The semantic scorer measures behavioral properties. These can legitimately differ:

| Case | Semantic Score | Corpus Label | Disagreement |
|------|---------------|--------------|--------------|
| `while_subscript` (arr traversal) | 0.80 | negative | Scorer correct — IS array traversal |
| `enumerate_print` (arr traversal) | 0.55 | negative | Borderline — IS array iteration |
| `single_membership_no_loop` (hash map) | 0.80 | negative | Scorer correct — IS membership test |
| `literal_dict_in_loop` (hash map) | 0.80 | negative | Scorer correct — IS dict membership |
| `dict_get_no_in` (hash map) | 0.50 | negative | Scorer correct — IS dict lookup |

**All failures are feature-level gaps, not scorer logic errors.** The scorer correctly weights the features it receives. The features need expansion.

## 6. Recommended Fixes (Ranked by Impact)

### Fix A: Support `not in` membership (hash_map_lookup)

**Impact:** +2 recall (2 FNs eliminated)
**Complexity:** Trivial — add `ast.NotIn` to the membership check in `_extract_access_features`
**Risk:** None — `not in` is semantically equivalent to `in` for membership detection

### Fix B: Credit direct iteration for array_traversal

**Impact:** +28 recall potential (all direct-iteration FNs)
**Complexity:** Low — add `has_collection_iteration` as evidence in `_score_array_traversal` at reduced weight (e.g., 0.15)
**Risk:** Moderate — may increase FPs if not gated carefully. Cross-pattern negatives like bubble sort also iterate collections.

### Fix C: Detect `.append()` as accumulation (prefix_sum)

**Impact:** +10 recall (range_sum_query FNs)
**Complexity:** Low — detect `list.append(expr)` in `_extract_accumulation_features`
**Risk:** Low — `.append()` in a loop with a running variable is strong accumulation evidence

### Fix D: Detect assignment-based accumulation (prefix_sum)

**Impact:** +2 recall (prefix_array_classic FNs)
**Complexity:** Medium — detect `x[i] = x[i-1] + expr` pattern
**Risk:** Low — specific pattern, unlikely to cause FPs
