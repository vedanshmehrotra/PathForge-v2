Notes on labels used beyond the quick-vocabulary list

The review guide explicitly allows "brute_force" as a corrected label (its own LC1 fam2/fam3 example). A few other families needed
a descriptive label not in the fixed vocabulary list (e.g. sort_and_rebuild, recursive_merge, iterative_insertion, dp_top_down,
recursive_dfs_by_depth, clean_and_compare_reverse, recursive_dfs_traversal). These follow the same plain-English, approach-
describing style as the provided vocabulary and are flagged above for your discretion -- swap in your own team's preferred term if
you have a house-style equivalent.

lc242_fam2 flagged REJECTED

The sheet's own description for this family says it "contains zero-evidence members" alongside one Counter-equality member. Since
coherence of the family (whether all members share one approach) can't be verified from what's given, this is the one case matching
the REJECTED criterion -- not because the visible code is wrong, but because the family's coherence is unconfirmed.
